Recrée Yedric seul, en 5 jours

Yedric est un widget IA embeddable qui permet aux utilisateurs d'un SaaS de le piloter en langage naturel. Au lieu de chercher dans les menus, l'utilisateur tape ce qu'il veut faire et le widget exécute l'action. Voici le plan pour construire ta propre version, pensée pour le marché francophone et européen, avec Claude Code.

Pourquoi c'est un bon pari

  • Un besoin universel chez les SaaS. Chaque fondateur veut rendre son produit « AI-native », mais construire un agent conversationnel intégré est complexe et coûteux. Un widget clé en main qui s'intègre en 30 minutes résout ce problème.
  • Une demande prouvée aujourd'hui. 238 upvotes et la 2e place de Product Hunt le jour du lancement. Le pitch « rends ton SaaS pilotable en parlant » parle directement aux développeurs.
  • Pas de concurrent direct en français/UE. Dust (français) est une plateforme complète d'assistants IA, pas un widget embeddable. IA Souveraine cible les grands comptes. Personne ne propose le widget plug-and-play avec hébergement UE et Mistral en option.
  • Techniquement abordable. Pas de modèle à entraîner : le function calling de Claude fait le gros du travail. Le reste, c'est un widget JS, un dashboard et des webhooks.
Ton angle de différenciation

La version française et souveraine : widget hébergé en UE via Supabase, Mistral disponible comme modèle alternatif à Claude/GPT, conformité RGPD annoncée dès la page d'accueil, et documentation en français pour les développeurs SaaS francophones qui n'ont pas le temps de lire de la doc en anglais.

Le MVP

Cinq fonctionnalités, pas une de plus pour la première version.

MVP

Dashboard développeur

Le créateur du SaaS enregistre ses actions (nom, description, paramètres). C'est le contrat entre le widget et le produit.

MVP

Widget JS embeddable

Un bouton flottant qui ouvre un chat. S'intègre en une ligne de code sur n'importe quel site.

MVP

NL → Action (function calling)

Claude reçoit le message + les actions disponibles, choisit la bonne et remplit les paramètres. Réponse en streaming.

MVP

Webhooks vers le SaaS

Quand Claude choisit une action, un POST part au webhook configuré. Le SaaS exécute et renvoie le résultat.

MVP

Personnalisation du widget

Couleur d'accent, position, message d'accueil, avatar. Prévisualisation en temps réel dans le dashboard.

  • Hors V1 : analytics avancés, support multi-langues automatique, marketplace de connecteurs pré-faits, SDK React/Vue natif.

Le plan jour par jour

Chaque jour a son prompt prêt à coller dans Claude Code. Lance-le dans un dossier vide, puis relis et teste avant de passer au suivant.

J1

Le widget et le dashboard

  • Créer le projet Next.js et le dashboard développeur.
  • Formulaire pour enregistrer les actions du SaaS (nom, description, paramètres).
  • Widget JS embedable : bouton flottant → chat.
Fin de journéeUn développeur enregistre ses actions et voit le widget apparaître sur une page de test.
Prompt Claude Code · J1
Crée une application Next.js (App Router, TypeScript, Tailwind), interface en français.
Page /dashboard : formulaire pour enregistrer des « actions » que le SaaS sait faire. Chaque action a un nom, une description et des paramètres définis en JSON Schema. Stocke-les en mémoire/fichiers JSON pour l'instant (la base arrive au jour 4).
Crée un composant React <YedricWidget /> : un bouton flottant en bas à droite qui ouvre un panneau de chat. L'utilisateur tape une phrase, le widget l'envoie à /api/chat avec l'identifiant de l'app et la liste des actions enregistrées.
Génère aussi un snippet <script> embedable qui charge le widget sur n'importe quel site externe (iframe ou shadow DOM).
Ajoute un fichier .env.example et un README expliquant comment lancer le projet.
J2

L'intelligence : NL → Action

  • Brancher l'API Claude avec function calling sur /api/chat.
  • Le backend traduit le message en action structurée.
  • Réponse en streaming dans le widget.
Fin de journéeUn utilisateur tape « crée un projet Marketing » et le widget identifie l'action et les paramètres.
Prompt Claude Code · J2
Branche l'API Claude (SDK Anthropic) sur la route /api/chat :
- Envoie le message utilisateur + la liste des actions enregistrées sous forme de tools (function calling / tool_use).
- Claude choisit l'action et ses paramètres, ou répond en texte si aucune action ne correspond.
- Affiche la réponse en streaming dans le widget (utilise ReadableStream).
- Ajoute un historique de conversation par session (stocké côté client dans le state du widget).
- Ajoute une page /dashboard/test avec un widget intégré et un panneau latéral qui affiche en temps réel l'action choisie par Claude et ses paramètres.
Gère les erreurs : si Claude ne trouve pas d'action, il répond poliment en texte.
J3

Webhooks et personnalisation

  • Système de webhooks vers le SaaS du développeur.
  • Gestion des réponses et erreurs.
  • Personnalisation visuelle du widget.
Fin de journéeQuand l'utilisateur demande une action, le SaaS la reçoit par webhook et le résultat s'affiche dans le chat.
Prompt Claude Code · J3
Ajoute un système de webhooks :
- Dans le dashboard, le développeur renseigne une URL de webhook globale ou par action.
- Quand Claude choisit une action, le backend envoie un POST JSON au webhook avec le nom de l'action, les paramètres et un token de vérification.
- Le SaaS répond avec un JSON (succès/erreur + message). Affiche le résultat dans le chat.
- Ajoute une page /dashboard/logs : historique des webhooks envoyés (date, action, statut, durée).
- Ajoute un onglet /dashboard/style : personnalisation du widget (couleur d'accent en hex, position bas-droite ou bas-gauche, message d'accueil, URL d'avatar). Prévisualisation en temps réel à côté du formulaire.
- Le snippet embed prend ces réglages en compte automatiquement.
J4

Comptes et paiement

  • Auth Supabase et base de données.
  • Abonnement Stripe.
  • Quotas et analytics basiques.
Fin de journéeUn développeur crée un compte, enregistre son app, et passe en Pro pour débloquer les requêtes illimitées.
Prompt Claude Code · J4
Ajoute Supabase au projet :
- Authentification par lien magique (email).
- Tables : apps (id, user_id, name, webhook_url, widget_config en JSON), actions (id, app_id, name, description, parameters_schema en JSON), logs (id, app_id, action_name, input, output, status, created_at), avec Row Level Security.
- Migre le stockage JSON vers Supabase.
Intègre Stripe :
- Stripe Checkout pour un abonnement mensuel « Pro » à 19 €.
- Webhook Stripe qui met à jour le statut du profil (free / pro) dans Supabase.
- Plan gratuit : 100 requêtes/mois, 5 actions max, 1 app. Compteur vérifié côté serveur.
- Portail client Stripe pour gérer l'abonnement.
Ajoute un tableau de bord analytics : nombre de requêtes ce mois, actions les plus utilisées, taux de succès des webhooks.
Donne-moi le SQL de migration à exécuter dans Supabase.
J5

Landing page et mise en ligne

  • Page d'accueil avec démo interactive.
  • Documentation développeur.
  • Déploiement sur Vercel.
Fin de journéeLe produit est en ligne, prêt à être présenté aux premiers développeurs.
Prompt Claude Code · J5
Crée la page d'accueil en français :
- Titre accrocheur : « Tes utilisateurs pilotent ton SaaS en parlant ».
- Démo interactive : un faux widget avec des actions pré-remplies (créer un projet, chercher un client, envoyer une facture) que le visiteur peut tester en direct.
- 3 bénéfices : intégration en 30 min, moins de tickets support, tes utilisateurs adoptent les features cachées.
- Section « Comment ça marche » en 3 étapes (enregistre tes actions, colle le snippet, tes utilisateurs parlent).
- Grille tarifaire (Gratuit / Pro 19 €/mois).
- FAQ centrée sur la sécurité et le RGPD (hébergement UE, données chiffrées, aucun accès aux données utilisateur).
Ajoute une page /docs : guide d'intégration pas à pas avec exemples de code (curl, JavaScript, React).
Ajoute les pages Mentions légales et Politique de confidentialité, les métadonnées SEO et les images Open Graph.
Liste toutes les variables d'environnement à configurer sur Vercel.

Les risques à connaître

La latenceChaque requête passe par Claude : 1 à 3 secondes de délai. Le streaming masque une partie de l'attente, mais certains utilisateurs préféreront toujours cliquer. Propose les deux.
Le coût des APIChaque message utilise des tokens Claude. Le plan gratuit (100 requêtes/mois) et le prix Pro (19 €) doivent couvrir le coût moyen par requête. Surveille ta marge dès la première semaine.
La sécuritéLe widget a accès aux actions du SaaS via webhooks. Un utilisateur malveillant pourrait tenter des injections de prompt pour déclencher des actions non souhaitées. Ajoute une confirmation côté SaaS pour les actions sensibles.
La concurrence arriveraYedric a une longueur d'avance, et Intercom ou Zendesk pourraient ajouter cette fonctionnalité. Ton avantage : la simplicité, le positionnement développeur solo, et le RGPD.
