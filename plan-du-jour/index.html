Recrée Deskcord seul, en 3 jours

Deskcord transforme ton serveur Discord en helpdesk : chaque conversation de tes visiteurs devient un thread Discord. Voici le plan pour construire ta propre version, open-source et auto-hébergeable, avec Claude Code.

Pourquoi c'est un bon pari

  • Un besoin quotidien. Les petites équipes et freelances paient 25 à 40 €/mois pour un chat client (Crisp, Intercom) alors qu'ils communiquent déjà sur Discord gratuitement.
  • Une demande prouvée. 75 upvotes sur Product Hunt le jour du lancement, un bot référencé sur top.gg, et un pricing validé entre 4 et 16 $/mois.
  • Pas de version open-source. Deskcord est propriétaire. Crisp (français, Nantes) ne fait pas de pont Discord natif. Chatwoot est open-source mais sans intégration Discord. Le créneau est libre.
  • Techniquement simple. Un bot Discord, un relay WebSocket et un snippet JS. Pas de modèle IA à entraîner, pas de données propriétaires.
Ton angle de différenciation

La version open-source et auto-hébergeable : zéro données stockées chez un tiers, déployable sur ton infra. Bonus : des réponses IA automatiques avec Claude quand l'équipe est absente.

Le MVP

Quatre fonctionnalités, pas une de plus pour la première version.

MVP

Widget JS embarquable

Un snippet <script> à coller sur n'importe quel site. Personnalisable : couleur, position, texte d'accueil. ~5 Ko.

MVP

Bot Discord + threads

Chaque nouveau visiteur ouvre un thread dédié dans un canal Discord. Messages bidirectionnels en temps réel.

MVP

Relay WebSocket

Serveur intermédiaire qui connecte le widget au bot Discord. Reconnexion automatique et indicateur de frappe.

MVP

Dashboard admin

Interface web pour configurer le widget, connecter ton serveur Discord et gérer l'abonnement Stripe.

  • Hors V1 : réponses IA automatiques, support Slack, application mobile dédiée, analytics de conversations.

Le plan jour par jour

Chaque jour a son prompt prêt à coller dans Claude Code. Lance-le dans un dossier vide, puis relis et teste avant de passer au suivant.

J1

Le cœur : bot Discord + relay

  • Créer le bot Discord avec discord.js et les permissions nécessaires.
  • Gérer les threads : un thread par visiteur, auto-archivage après inactivité.
  • Monter le serveur WebSocket avec Socket.io.
  • Tester le flux complet : message → Discord → réponse → widget.
Fin de journéeTu envoies un message depuis un script de test, il apparaît dans un thread Discord. Tu réponds dans Discord, la réponse revient dans le script.
Prompt Claude Code · J1
Crée un projet Node.js (TypeScript) avec deux parties :
1. Un bot Discord (discord.js v14) qui écoute un canal « support ». Quand il reçoit un message via le serveur WebSocket, il crée un thread (ou réutilise le thread existant pour ce visiteur, identifié par un UUID). Quand quelqu'un répond dans le thread, le bot envoie la réponse au serveur WebSocket.
2. Un serveur Socket.io qui accepte les connexions des widgets. Chaque widget s'identifie par un visitorId (UUID). Les messages du widget sont relayés au bot Discord via un EventEmitter interne, et les réponses Discord sont renvoyées au bon widget via son socket.
Ajoute un fichier .env.example (DISCORD_TOKEN, DISCORD_GUILD_ID, DISCORD_CHANNEL_ID, PORT) et un script de test en ligne de commande qui simule un visiteur.
J2

Le widget + le dashboard

  • Créer le widget de chat en Vanilla JS avec Shadow DOM.
  • Personnalisation via attributs data- sur le script.
  • Connexion au serveur Socket.io.
  • Créer le projet Next.js pour le dashboard admin.
Fin de journéeTu colles un <script> sur une page HTML locale, le widget apparaît en bas à droite. Tu tapes un message, il arrive dans Discord, tu réponds, ça revient dans le widget.
Prompt Claude Code · J2
Crée un widget de chat en Vanilla JS (~5 Ko minifié), interface en français :
- Bouton flottant en bas à droite avec badge de notification
- Fenêtre de chat : messages, champ de saisie, indicateur « en train d'écrire »
- Se connecte au serveur Socket.io du jour 1 via un visitorId UUID (stocké en localStorage)
- Personnalisable via attributs data- sur la balise script : data-color, data-position (left/right), data-welcome, data-company
- Shadow DOM pour éviter les conflits CSS avec le site hôte
- Distribué comme un seul fichier JS auto-exécutable
Puis crée un projet Next.js (App Router, TypeScript, Tailwind) avec :
- Page /dashboard : formulaire de configuration du widget (couleur, position, texte, Discord channel ID)
- Aperçu en direct du widget dans un iframe
- Route API /api/widget/[userId].js qui sert le JS du widget avec la config injectée
J3

Paiement, landing et mise en ligne

  • Intégrer Supabase pour l'auth et le stockage de configuration.
  • Intégrer Stripe pour l'abonnement mensuel.
  • Créer la page d'accueil en français.
  • Déployer sur Vercel + Railway.
Fin de journéeLe produit est en ligne. Un visiteur peut s'inscrire, payer, configurer son widget et l'installer sur son site.
Prompt Claude Code · J3
Intègre Supabase et Stripe au projet Next.js :
- Auth par lien magique (email) avec Supabase.
- Table widget_configs (id, user_id, color, position, welcome_text, discord_channel_id, discord_token_encrypted, plan) avec Row Level Security.
- Stripe Checkout pour un abonnement « Solo » à 9 €/mois. Webhook /api/stripe/webhook qui met à jour le plan dans Supabase.
- Portail client Stripe pour gérer l'abonnement.
- Page d'accueil en français : titre accrocheur, démo animée du widget, 3 bénéfices (gratuit via Discord, 3 min d'installation, zéro donnée stockée), grille tarifaire (Gratuit 1 site / Solo 9 € illimité / Team 29 € + IA), FAQ.
- Pages Mentions légales et Politique de confidentialité.
Prépare le déploiement : liste des variables d'environnement pour Vercel et Railway, instructions de mise en production.

Les risques à connaître

Discord peut changer ses conditionsL'API est stable depuis des années, mais surveille les mises à jour. Plan B : ajouter le support Slack pour diversifier.
Latence du relayLe serveur WebSocket ajoute un intermédiaire. Teste la latence et optimise la persistance des connexions dès le premier jour.
Marché de nicheLes gros clients n'utiliseront jamais Discord pour le support. Cible les indie makers, freelances et équipes de moins de 10 personnes.
