Pourquoi c'est un bon pari

  • Un besoin universel. Tout le monde se dispute pour la vaisselle, le ventilateur ou « je le fais après ». Ces micro-conflits n'ont aucun outil ludique pour les désamorcer.
  • Un concept viral. Les verdicts du capybara se partagent naturellement : drôles, visuels, parfaits pour les stories et TikTok. 77 upvotes dès le premier jour sur Product Hunt.
  • Aucun concurrent en France. Les plateformes de médiation françaises (Socrate Médiation, MARD) sont sérieuses. Aucune version ludique et IA n'existe en francophonie.
  • Techniquement trivial. Un formulaire, un appel API à Claude, une interface soignée. Pas de modèle à entraîner, pas de données propriétaires.
Ton angle de différenciation

La version française, bienveillante et personnalisable : interface en français, ton chaleureux, plusieurs personnages juges (capybara, chat, flamant rose), et un angle « bien-être du couple » qui parle au public francophone.

Le MVP

Cinq fonctionnalités, pas une de plus pour la première version.

MVP

Formulaire de dispute scellé

Quatre questions par personne. Chaque côté est invisible pour l'autre, seul le juge IA lit les deux.

MVP

Verdict IA bienveillant

Répartition de la faute (jamais 100/0), le vrai sujet en une phrase, et un petit défi à faire ensemble ce soir.

MVP

Reveal simultané

Le verdict s'ouvre en même temps sur les deux téléphones via un lien partagé.

MVP

Galerie publique

Les verdicts les plus drôles, anonymisés, visibles par tous. Moteur de viralité.

MVP

Auto-suppression à 30 jours

Tout est effacé automatiquement. Respect de la vie privée par design.

  • Hors V1 : application mobile native, statistiques du couple, abonnement famille, intégration WhatsApp.

Le plan jour par jour

Chaque jour a son prompt prêt à coller dans Claude Code. Lance-le dans un dossier vide, puis relis et teste avant de passer au suivant.

J1

Le tribunal capybara

  • Créer le projet Next.js avec la page de création de dispute.
  • Formulaire en 4 questions + lien de partage pour l'autre personne.
  • Route API qui envoie les deux côtés à Claude et renvoie le verdict en JSON.
  • Page de verdict avec avatar capybara, répartition visuelle et défi du soir.
Fin de journéeDeux personnes remplissent le formulaire et reçoivent un verdict capybara.
Prompt Claude Code · J1
Crée une application Next.js (App Router, TypeScript, Tailwind), interface en français.
Page /nouveau : formulaire de dispute en 4 questions (« Que s'est-il passé ? », « Qu'est-ce qui t'a le plus agacé ? », « Ce que l'autre devrait faire », « Ta part de responsabilité »). À la soumission, génère un lien unique à envoyer à l'autre personne.
Page /dispute/[id] : si la 2e personne n'a pas répondu, affiche le même formulaire. Si les deux ont répondu, appelle la route /api/verdict.
Route /api/verdict : envoie les deux côtés à l'API Claude avec un prompt structuré qui demande un JSON { repartition: number (25-75), vrai_sujet: string, defi_du_soir: string, commentaire: string }. Le juge est un capybara bienveillant, jamais moralisateur, toujours drôle.
Page /verdict/[id] : affiche le verdict avec un avatar capybara, une barre de répartition visuelle (couleurs douces), le vrai sujet en gros, le commentaire, et le défi du soir dans un encadré vert.
Stocke les disputes dans un fichier JSON local pour le prototype (on passera à Supabase demain).
Ajoute un fichier .env.example avec ANTHROPIC_API_KEY.
J2

Comptes, galerie, personnages

  • Connexion par lien magique avec Supabase (région UE).
  • Sauvegarde des disputes et verdicts en base.
  • Galerie publique des verdicts anonymisés.
  • Choix du personnage juge (capybara, chat, flamant rose).
Fin de journéeUn couple crée un compte, retrouve ses disputes passées, et partage son verdict préféré.
Prompt Claude Code · J2
Ajoute Supabase au projet :
- Authentification par lien magique (email).
- Table disputes (id, user1_id, user2_token, questions_user1, questions_user2, verdict, judge_character, created_at) avec Row Level Security.
- Table gallery (id, dispute_id, anonymized_verdict, published_at) pour les verdicts rendus publics par les utilisateurs.
- Page /galerie qui affiche les verdicts anonymisés les plus récents, avec pagination.
- Sur la page verdict, ajoute un bouton « Publier dans la galerie » (anonymise les réponses, garde le verdict et le défi).
- Ajoute le choix du personnage juge au formulaire : capybara (défaut), chat, flamant rose. Passe le personnage au prompt Claude pour adapter le ton.
- Quota : 3 disputes par mois pour les comptes gratuits, vérifié côté serveur.
- Cron Supabase (pg_cron) : supprime les disputes de plus de 30 jours.
Donne-moi le SQL de migration.

Les risques à connaître

Revenus incertainsC'est une app de divertissement, pas un SaaS critique. Le pricing doit rester bas et la croissance repose sur la viralité, pas sur le marketing payant.
Le sujet est sensibleLes disputes de couple peuvent toucher des sujets douloureux. Le prompt IA doit cadrer strictement vers le fun et la bienveillance. Jamais de conseil thérapeutique, toujours un disclaimer visible.
La viralité n'est pas garantiePrévois des mécaniques de partage dès le jour 1 : image Open Graph du verdict, galerie publique, bouton de partage. Sans ça, l'app reste invisible.
